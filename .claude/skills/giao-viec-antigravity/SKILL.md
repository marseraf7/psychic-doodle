# Giao việc cho Antigravity

Mục tiêu: Claude Code dồn token và thời gian vào việc khó (tìm nguyên nhân gốc, thiết kế, engine, server, bảo mật);
việc đơn giản nhưng tốn token / thời gian thì giao Antigravity chạy song song. Luật chung của hai agent: `AGENTS.md`.

## 1. Việc này có nên giao không?

Giao khi **cả ba** đúng:
1. Đầu vào và tiêu chí xong viết được rõ trong một Issue (không cần hiểu sâu kiến trúc).
2. Sai thì rẻ: kết quả là báo cáo, hoặc sửa nhỏ trong phạm vi hẹp, Claude Code review được nhanh.
3. Tốn thời gian chờ / token đọc nhiều hơn tốn suy nghĩ.

| Giao Antigravity (`agent:agy`) | Claude Code tự làm |
|---|---|
| Chạy test lặp N lần, đo tỉ lệ lỗi, chạy ma trận trình duyệt | Tìm nguyên nhân gốc, thiết kế thí nghiệm chẩn đoán |
| Kiểm trên máy thật / trình duyệt thật / điện thoại (máy session không có WebKit, không có Safari) | Server, engine, Rapfi / NNUE, thuật toán |
| Đọc log dài rồi tóm tắt theo mẫu "Báo cáo gọn" | Bảo mật, phiên đăng nhập, quyền, dữ liệu người dùng |
| Soát chuỗi dịch đủ vi / en / ru / zh, chữ tràn, giao diện 360 px | Cấu trúc CI, ruleset, workflow |
| Audit chỉ đọc (vòng đời Worker, chỗ gọi API cũ, file sắp quá 400 dòng) | Thay đổi nhiều file, đổi API / giao thức / schema |
| Viết test theo đặc tả đã có; sửa lỗi nhỏ đã rõ nguyên nhân | Review cuối và merge |
| Cập nhật tài liệu, README, ảnh chụp màn hình | Việc mà sai sẽ mất dữ liệu / mất người chơi |

Không giao: việc cần quyết định thiết kế, việc đang dở giữa chừng của Claude Code, việc đụng file dễ xung đột
(`caro/sw.js`, `caro/index.html`, `caro/i18n-*.js`) cùng lúc với PR đang mở của Claude Code.

## 2. Viết Issue giao việc

Tạo bằng `gh api -X POST repos/<owner>/<repo>/issues` với `labels: ["agent:agy"]`, theo mẫu
`.github/ISSUE_TEMPLATE/nhiem-vu-agent.yml`. Bắt buộc có:
- **Mục tiêu** – vì sao cần (1–3 câu, kèm số PR / Issue liên quan).
- **Phạm vi** – file được sửa, hoặc "không sửa code".
- **Các bước / lệnh chạy** – chép được ngay (kèm cách đặt biến trên Windows PowerShell).
- **Tiêu chí xong** – checkbox kiểm được.
- **Nộp kết quả** – việc chỉ báo cáo: PR `reports/<số-issue>-<tên>.md` từ nhánh `agy/report-<số-issue>`; việc sửa code:
  PR `Closes #<số>`. Nhắc định dạng "Báo cáo gọn" (AGENTS.md).
- Cuối Issue: chữ ký `_Generated by [Claude Code](https://claude.ai/code)_`.

Gom việc: một Issue một chủ đề; nhiều việc nhỏ cùng loại (vd. soát dịch 3 trang) gộp một Issue.
Sau khi tạo: báo người dùng số Issue trong một dòng. Không chờ, làm tiếp việc của mình.
(Đã bỏ nhóm Lark theo yêu cầu người dùng: không đọc, không theo dõi, không gửi tin Lark.)

## 3. Nhận và kiểm kết quả

- Antigravity nộp qua **PR** → `subscribe_pr_activity` để tự nhận sự kiện (không phải chờ người dùng chuyển lời).
- Đọc báo cáo trước, chỉ mở log khi báo cáo thiếu. Lỗi e2e trên CI: đọc annotation
  (`gh api repos/<owner>/<repo>/check-runs/<id>/annotations`) – `helpers.js` in sẵn `::error` cho mỗi bước
  FAIL / trang sập / dừng giữa chừng; chỉ tải log job khi annotation không đủ.
- **Kiểm chứng, đừng tin ngay**: test mới có thật sự đỏ trên code cũ không (chạy lại với file cũ); số liệu có
  khớp CI không. Ví dụ đã gặp (PR #26): e2e mới của Antigravity không tái hiện được lỗi vì đặt cài đặt sai thứ tự.
- Review theo `AGENTS.md`: 🔴 chặn, 🟡 gợi ý; merge khi 5 check bắt buộc xanh.
- Bài học rút ra (lỗi Antigravity hay mắc, chỗ Issue viết thiếu) → thêm vào `AGENTS.md` hoặc mục 4 dưới đây.

## 4. Bài học đã rút ra

- Test tái hiện lỗi phải chứng minh **đỏ trên code cũ** – ghi rõ yêu cầu này trong Issue.
- Cùng một tài khoản GitHub cho hai agent: phân biệt bằng dòng `Agent: agy` trong commit.
- PR có test phải kèm dòng kết quả cuối của từng trình duyệt; vẫn tự chạy lại ít nhất Chromium trước khi duyệt.
  Ví dụ đã gặp (PR #27): bài bấm tab `study` không tồn tại, dừng ở mục 2 – lần nộp đầu chưa từng chạy hết bài.
- Việc cần WebKit / Safari / iPhone: luôn giao Antigravity (máy session của Claude Code chỉ có Chromium).
- Dẫn chứng bằng run ID / job ID phải ghi kèm **tên job** (vd. Android 34 / 35) và **commit** (`head_sha`), đã đối
  chiếu qua API (`get_workflow_job`). Ghi rõ trong Issue. Ví dụ đã gặp (PR #55): 2 lần dẫn job "chạy lại cùng commit"
  nhưng thật ra là commit khác, một job còn sai API; trước đó còn chép đoạn "nhật ký máy chủ" không có trong log thật.
